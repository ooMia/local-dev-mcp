# 읽기 관측에 근거한 파일 수정과 읽기 전용 예외

IDE와 함께 사용하는 workspace에서 파일 수정을 제공한다. 수정은 유효한 `read_ref`로 보관한 원문 구간을 근거로 하며,
관측 당시의 전체 파일 버전과 쓰기 직전 확인한 버전이 다르면 거부한다. 오래된 관측을 현재 파일에 자동 적용하지 않기 위한 선택이다.
이는 임의의 외부 프로그램이 검사 직후 저장하는 것까지 차단한다는 보장은 아니다.

한 수정 호출은 기존 UTF-8 파일 하나의 관측 구간 전체를 새 문자열로 교체한다.
빈 기존 파일도 유효한 관측 참조를 발급해 지원하며, 비어 있지 않은 파일의 EOF 밖 요청과 구분한다.
성공 후 해당 구간을 실제로 재관측한 경우 새 버전과 새 `read_ref`를 반환해 연속 수정을 지원한다.
재관측 실패는 교체 실패로 바꾸지 않고 실제 교체 여부와 다음 읽기 방법을 안내한다.

사용자의 중간 편집으로 오래된 참조가 되었더라도 작업을 재개할 방법을 제공해야 한다.
과거 줄 번호를 현재 파일의 수정 위치로 그대로 신뢰하거나, 후속 확인 실패를 이유로 최신 사용자 내용을 되돌리지 않는다.

없는 파일의 생성은 관측 구간 교체와 분리해 기존 경로를 덮어쓰지 않도록 한다. 필요한 부모 디렉터리는 호출자가 명시적으로 선택한다.
단일 파일 삭제는 같은 경로의 유효한 관측과 전체 버전 일치를 요구한다. 생성·삭제는 요청 ID에 적용 결과를 결합해 응답 유실 뒤
같은 작업을 반복하지 않으며, 이를 원문 관측 참조나 영구 복구 기록으로 취급하지 않는다.
삭제는 자체 휴지통·백업을 만들지 않고 Git index·HEAD도 변경하지 않는다. Git에 없는 최신 내용의 복구는 보장하지 않는
명시적인 계약이며, 자동 commit·stage·stash로 사용자의 형상 관리 상태를 바꾸지 않는다.

개발 환경은 editable 설치를 유지한다. Agent가 정책 집행·비밀 사용 코드를 정책 우회 목적으로 변경하지 않는다고 가정하며,
별도의 고정 설치본이나 자기 변조 방어를 이번 기반 작업의 필수 조건으로 삼지 않는다.
일반적인 권한 위반·오래된 관측·쓰기 실패를 검사하는 책임은 유지한다.

파일 접근 정책은 `filesystem.allowed_paths`의 문자열 배열을 유지하고, `read_only_paths`를 더 높은 우선순위의 쓰기 금지 범위로 둔다.
허용 범위 안에서는 조회와 수정을 허용하되 읽기 전용 경로와 그 하위는 직접 수정하지 않는다.
더 구체적인 허용 경로로 읽기 전용 제한을 해제하지 않으며, 읽기 전용 지정만으로 허용 범위 밖의 읽기를 허용하지 않는다.
`read_only_paths`의 생략과 빈 목록은 읽기 전용 예외가 없다는 의미다.
기존 설정 형식을 유지하면서 수정 금지 대상을 명시하기 위한 선택이며, 기존 배열 형식을 거부하는 전환은 필요하지 않다.

Workspace 내 `.gitignore` 규칙으로 제외되는 경로도 직접 수정에서는 읽기 전용으로 취급한다.
읽기 전용은 직접 수정의 제한이며, Git의 stage·commit과 등록된 CLI 작업의 부수 동작은 별도 작업 계약으로 다룬다.
공개 도구 입력·파일 접근·agent에게 반환하는 Git 결과에서 경로 정책을 검사한다.
Git 내부 메타데이터와 서명 기능에 필요한 접근 권한은 agent의 일반 파일 조회 권한과 구분한다.
공개 Git 결과는 보호 경로의 원문을 생성한 뒤 마스킹하는 대신, 변경 경로를 확인해 허용된 범위만 반환한다.

`.env`를 사용하는 내부 기능은 agent에게 그 원문을 제공하지 않는다.
등록된 CLI 작업은 서버 전용 설정을 제외한 프로젝트 공통 환경을 사용하며, 알려진 비밀값의 출력 처리는
[작업 진단 계약](../tools/tasks/README.md#진단과-출력-보호)을 따른다.
신뢰한 프로젝트 코드와 hooks·필터의 모든 OS 파일 접근을 강제로 격리하는 구현은 추가하지 않는다.
이는 editable 개발 환경에서 의도적인 정책 우회를 하지 않는다는 전제를 따른다.
다른 소스·로그·생성물에 복제된 비밀을 일반적으로 추적하거나 자동 마스킹하는 기능도 제공하지 않는다.
`.env` 원문은 비공개로 유지하고 credential과 미분류 값은 비밀로 취급한다.
기능상 공개가 필요한 identity·서명 설정·공개키 fingerprint 같은 metadata는 비밀과 구분해 정해진 결과에서만 제공한다.

읽기·쓰기 모두를 금지하는 `denied_paths`를 별도로 두고 `allowed_paths`보다 우선 적용한다.
루트 `config.toml`과 workspace 내 모든 `.gitignore`는 기본적으로 직접 수정에서 보호한다.
사용자가 `--allow-policy-edits`로 시작하면 이 기본 쓰기 금지만 해제해 MCP로 정책 파일을 관리할 수 있다.
나머지 경로·ignore·관측 검사는 유지하며, Agent가 호출 인자나 설정 파일로 실행 중인 opt-out 모드를 바꿀 수는 없다.
`config.toml` 변경은 재시작 후, `.gitignore` 변경은 다음 작업부터 적용하는 기존 수명을 유지한다.

쓰기 응답은 이 요청의 실제 교체 여부와 후속 관측의 성공 여부를 구분하고, 실패 원인과 다음 호출 방법을 안내한다.
교체 후 관측 실패나 응답 유실을 무변경으로 해석해 자동으로 다시 쓰지 않는다.

사용자 편집으로 충돌하면 현재 내용을 보존한 채 재조회하고 수정안을 재구성해 재개한다.
관측 구간이 같아 보여도 전체 버전 조건을 자동 완화하거나 과거 줄 번호로 수정안을 재적용하지 않는다.
실행 가능한 설정과 현재 동작은 [설정 계약](../configuration.md)과 [Workspace 계약](../tools/workspace/README.md)이 소유한다.
