# ADR 0010: CLI와 MCP의 명시적 PR squash 및 결과 검증

- 상태: Accepted
- 결정일: 2026-11-06
- 범위: 원격 PR 병합 메시지, 독립 MCP 병합 권한, 실제 결과 확인
- 부분 대체: [ADR 0006](0006-native-pr-workflow-mvp.md)의 Actions 전용 통합 경로와 병합 요청만으로 끝나는 관측 범위. PR + squash 및 출처 정책은 유지한다.

## 결정과 이유

PR 생성 전의 원본 커밋은 아직 없는 PR 번호를 기록할 수 없다. GitHub의 기본 squash 메시지는
원본 커밋 메시지를 재사용할 수 있으므로, 최종 PR 출처를 원본 메시지나 저장소의 표시 기본값에 맡기지 않는다.
기존 CLI가 출처를 명시하더라도 MCP에서 병합까지 이어지는 기능이 없으면 다른 경로에서 이 규칙이 빠질 수 있다.

CLI와 MCP는 한 GitHub 병합 구현을 공유한다. 실제 PR 메타데이터에서 고정한 제목·출처 메시지를 만들고,
검토한 head와 계획 digest를 재확인한 뒤 조건부 direct squash 요청에 메시지를 명시한다.
MCP 조회와 쓰기는 독립 논리 권한으로 분리하며, 기존 게시 권한에 병합 권한을 묵시적으로 추가하지 않는다.
Draft의 Ready 전환, auto-merge, merge queue, 관리자 우회와 브랜치 삭제는 제공하지 않는다.

요청 종료 코드만으로 완료를 판정하지 않는다. 실제 PR의 merge SHA와 해당 커밋의 메시지·단일 부모를
다시 관측하여 확인한 결과만 성공으로 보고한다. 응답 유실은 결과 관측으로 처리하고 자동 재병합하지 않는다.
이미 병합된 PR도 새 쓰기 없이 진단한다. 메시지 불일치를 역사 재작성으로 고치지 않는다.

원격 보호 규칙이 없는 환경에서는 다른 UI/API의 병합까지 강제하지 못한다. 기존에 보류한 정확한 head의
CI 성공 직접 확인은 이번 결정에 포함하지 않는다. 도구의 메시지 검증 성공과 CI·로컬 전체 검사 성공을 구분한다.
Actions 통합 workflow는 계속 사용할 수 있으며, 같은 CLI 구현을 실행한다.

현재 입력·반환값·메시지 비교와 복구 절차는 [원격 PR 계약](../tools/git/remote-pr.md#명시적-pr-병합)과
[workflow 계약](../tools/workflow/README.md#기능-통합)이 소유한다.
