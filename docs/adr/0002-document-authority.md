# ADR 0002: 문서 권한 계층과 디렉터리별 에이전트 지침

- 상태: Accepted
- 범위: 저장소 전체의 문서 소유권·결정 충돌·에이전트 지침
- 결정일: 2026-10-30

## 맥락

루트 지침, 운영 계약, 개발 규약, 도구별 계약, 검증 절차와 연구 근거가 서로 다른 목적을 가진다.
동일한 판단을 여러 위치에서 재정의하거나 과거 조사 가설을 현재 결정처럼 읽으면 변경 방향이 어긋난다.

## 결정

1. 저장소 전체의 작업 원칙은 루트 `AGENTS.md`가 진입점이다. 해당 문서는 채택된 결정과 각 소유 문서를 **참조**하며 긴 규약을 복제하지 않는다.
2. 채택된 저장소 수준의 설계 결정은 `docs/adr/`가 소유한다. 현재 운영·사용자 계약은 `docs/configuration.md` 및 `docs/tools/*/README.md`, 구현·배치 규약은 `docs/conventions.md`가 소유하며 모두 채택된 상위 결정과 일치해야 한다.
3. `docs/design.md`는 실제 모듈 연결과 채택 이유를 설명하고, `docs/testing.md`는 검사 절차·증거의 범위를 정한다. `docs/research/`는 조사 당시의 근거와 후보를 보존하되 현재 동작·권한을 선언하지 않는다.
4. 디렉터리별 `AGENTS.md`는 해당 범위에 필요한 **추가 지침**만 기록한다. 하위 파일이 상위 지침·채택된 ADR을 묵시적으로 덮어쓰지 않도록 구성하며, 독립적인 정책 복사본을 만들지 않는다.
5. 상위 결정, 사용자 계약, 구현 또는 테스트가 어긋나면 하위 문서의 문구만 고쳐 불일치를 은폐하지 않는다. 변경된 의도·영향·검증을 확인한 후 소유 문서와 코드·테스트를 같은 변경에서 정합화한다. 상위 결정을 바꿀 때는 기존 ADR의 상태와 대체 관계를 명시한다.

## 범위 및 예외

이는 저장소 **내부**의 문서 관리 규약이다. 시스템·개발자·사용자 지시보다 프로젝트 문서가 우선한다는 뜻은 아니다.
Codex 등 일부 에이전트는 가까운 `AGENTS.md`를 뒤에 읽으므로 실제 우선순위가 충돌할 수 있다.
따라서 하위 `AGENTS.md`는 상위 내용을 재정의하지 않도록 작성·리뷰한다. 문서 디렉터리의 깊이가 도구 자체의 강제 권한 경계를 만들지는 않는다.

## 적용

문서 목록과 소유권은 [문서 지도](../README.md)에, 변경 완료 조건은 [개발 규약](../conventions.md#변경-완료-조건)에 둔다.
기존 파일 접근 결정은 [ADR 0001](0001-observed-file-edits-and-access.md)이며 본 결정이 이를 대체하지 않는다.
