# ADR 0011: 채팅 도구를 통한 PR 검사 조회와 Ready 전환

- 상태: Accepted
- 결정일: 2026-11-06
- 범위: 정확한 PR head의 CI 관측, 명시적 Ready 전환, squash 후 원격 기준선 취득
- 부분 대체: [ADR 0010](0010-deterministic-pr-merge.md)의 Ready 전환 제외 범위. 메시지·병합 검증과 CI 직접 강제 보류는 유지한다.

## 결정과 이유

사용자는 기능별 커밋의 게시부터 원격 main 병합까지 LOCAL-DEV-MCP 채팅 도구로 관리하고,
현재 구현을 손실 없이 반영하도록 목표를 확정했다. Draft 생성과 병합 도구 사이에 남은
Ready 전환·CI 조회를 외부 클라이언트나 사용자 수동 조작에 맡기는 흐름으로는 이 목표를 충족하지 못한다.

읽기 도구는 실제 PR head와 해당 커밋에 붙은 검사 결과를 결합해 반환한다.
GitHub Actions의 `Project quality`를 성공·진행 중·실패·누락·확인 불가로 구분하며,
불완전 조회나 다른 head의 성공을 현재 PR의 검증으로 사용하지 않는다.
동일 이름의 성공 한 건으로 다른 실패·진행 중 검사를 숨기지 않는다.

Ready 전환은 별도 `gh.pr.ready` 권한과 검토한 head·메시지 계획을 요구한다.
병합 권한에서 자동 파생하지 않고 실제 전환 결과를 다시 관측한다.
GitHub Ready API의 원자적 head 조건 부재는 후속 검증으로 관측하되 완전히 방지한 것으로 표현하지 않는다.
Ready 전환 자체를 리뷰 승인이나 CI 성공으로 해석하지 않는다.

CI 성공을 merge 명령 내부에서 직접 강제하는 보완은 계속 보류한다.
채팅 에이전트는 정확한 head의 `Project quality` 성공과 전체 rollup·병합 가능 상태를 확인한 뒤
명시적 Ready·조건부 squash·실제 커밋 검증을 이어간다. 원격 보호 부재를 도구의 강제성으로 포장하지 않는다.

원격 squash 후 새 SHA가 아직 로컬에 없어도 상태 조회가 가능해야 한다.
조상 관계를 모르면 이를 명시하고, 취득 도구는 관측한 main 객체만 먼저 내려받은 뒤
fast-forward 여부를 검사하고 예상 이전 값에 대한 비교·교체로 추적 Ref만 갱신한다.
로컬 main·원본 브랜치·작업 파일을 자동 재작성하지 않는다.

권한·입력·상태 판정·재시작과 복구 절차는 [원격 PR 계약](../tools/git/remote-pr.md)이 소유한다.
